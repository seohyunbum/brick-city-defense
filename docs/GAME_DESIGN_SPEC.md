# 브릭 시티 게임 설계 규격

- 문서 버전: 1.0
- 기준일: 2026-08-19
- 상태: 승인 가능한 목표 규격. `현재`로 표시한 항목만 구현 증거가 있음
- 제품명: 브릭 시티 — 브릭 몬스터 방어전

## 1. 판정 기준

이 문서는 아이디어 목록이 아니라 구현·검수 계약이다. `목표`는 코드, 자동 테스트, 플레이테스트 증거가 모두 연결돼야 `현재`로 승격한다. 현재 버전은 밝고 일관된 브릭 시각 언어와 손맛이 있는 단일 스테이지 프로토타입이지만, 시민·도시 방어 규칙과 진행 체계가 없어 고품질 완성판으로 보지 않는다.

| 구분 | 현재 증거 | 목표/차단 기준 |
| --- | --- | --- |
| 실행 | `file://`, GitHub Pages, Windows 바로가기 | 두 경로 회귀 0건 유지 |
| 플레이 | 무기 3, 스킬 3, 적 4, 10웨이브 | 12~18분 세션, 역할 중복 없는 선택 |
| 방어 | 적은 플레이어를 추적, 시민은 도망만 침 | 시민/거점 상태가 승패와 보상에 실제 영향 |
| 진행 | 점수와 로컬 최고점수 | 런내 선택 3회 이상, 영구 과금·계정 없음 |
| 도시 | 경찰서·크레인·헬기 등 랜드마크 | 3방향 전투, 2개 비처치 목표, 생활 이벤트 |
| 품질 | 자동 기능 스모크와 렌더 수치 | 하드웨어·접근성·오디오·아동안전 게이트까지 통과 |

## 2. 비전과 설계 기둥

한 문장 비전: “손으로 조립한 듯한 도시가 실제로 살아 움직이고, 아이가 즉시 이해할 수 있는 도구로 시민과 거점을 지키는 1인칭 브릭 방어전.”

1. 만져지는 장난감 도시: 스터드, 플라스틱 광택, 명확한 조립선, 작은 생활 장면이 가까이서도 설득력 있어야 한다.
2. 읽히는 전투: 공격 예고, 피격, 범위, 보상은 0.5초 안에 구별돼야 하며 후처리가 적 실루엣을 가리지 않는다.
3. 아이에게 공정한 실패: 첫 60초는 학습 구간이고, 실패 원인은 화면과 소리로 설명되며 유혈·공포·과금 압박이 없다.
4. 지킨 결과가 보이는 도시: 시민·경찰서·차량·가로등 등 방어 대상의 상태가 게임 규칙과 장면에 반영된다.

비목표: 공식 완구 제품·세트·캐릭터의 복제, 사실적 총기·폭력, 계정/채팅/광고/결제, 무한 오픈월드, 네트워크 멀티플레이. 친구 공유는 같은 URL로 각자 플레이한다는 뜻이며 현재 협동 플레이를 의미하지 않는다.

## 3. 대상과 세션

- 1차 플레이어: 보호자와 함께 또는 혼자 PC를 사용하는 어린이·가족
- 1차 플랫폼: Windows 11 데스크톱, 최신 Edge/Chrome, 키보드+마우스, 16:9 1080p
- 보조 호환: 터치 UI. 데스크톱 품질을 희생해 모바일을 우선하지 않는다
- 목표 세션: 10웨이브 12~18분, 첫 의미 행동 30초 이내, 재시작 10초 이내
- 학습 목표: 신규 사용자 10명 중 8명이 성인 도움 없이 3분 안에 웨이브 1 완료

## 4. 코어 루프

목표 루프는 `위협 확인 → 무기/두루마리 선택 → 시민·거점 방어 → 스터드 회수 → 웨이브 사이 강화 선택 → 도시 상태 회복 → 다음 방향 대비`다.

현재 루프는 `플레이어 추적 적 처치 → 탄약/마나 회수 → 다음 웨이브`다. 따라서 README의 “시민을 지킨다”는 정서적 설명일 뿐 규칙의 진실이 아니다. 다음 Defense Objective가 구현되기 전에는 제품 심사에서 생존형 arena shooter로 판정한다.

### Defense Objective P0 규격

- 도시 무결도 100으로 시작. 시민 구조 실패, 거점 피격 시 감소하며 0이면 패배한다.
- 플레이어 하트 0도 패배지만, 플레이어가 살아 있어도 도시 무결도 0이면 패배한다.
- 시민은 공격 불가. 위험 구역에서 안전 구역으로 이동시키거나 적의 주의를 끄는 방식으로 보호한다.
- 웨이브 사이에 `탄약 보급`, `도시 수리`, `마나 강화` 중 하나를 선택한다. 선택은 되돌릴 수 없고 즉시 효과가 보여야 한다.
- 수락 기준: 시민/거점 상태를 무시한 플레이와 보호한 플레이의 점수·보상·승패가 명확히 달라야 한다.

## 5. 3C: 캐릭터·카메라·컨트롤

현재 기준값은 FOV 70(세로 화면 82), 걷기 22, 달리기 34, 눈높이 4.6이다. 숫자 변경은 `src/loadout.js` 또는 설정 정본에서만 한다.

- 카메라: FOV 60~100 설정, 감도 0.5~2.0, 수직 반전, head-bob 0~100%, DoF on/off를 제공한다.
- 입력: WASD·Shift·1~6·마우스 양 버튼의 전체 흐름이 키보드만으로도 시작/일시정지/재개 가능해야 한다.
- 이동: 충돌·경사·경계에서 순간이동이 없어야 하며, 채널링 감속은 HUD와 손 애니메이션으로 설명한다.
- 조준: 색만으로 피격을 알리지 않고 crosshair, hit mark, 음향을 함께 쓴다.

## 6. 전투 역할

| 도구 | 고유 역할 | 실패 신호 | 수락 시나리오 |
| --- | --- | --- | --- |
| 검 | 탄약 없는 근거리 다수 제어 | 사거리 밖 휘두름 | 근접 3체를 총보다 효율적으로 처리 |
| 총 | 단일 표적·비행 적 지속 공격 | 탄약 0, 명확한 dry 신호 | 배트를 검보다 안정적으로 처리 |
| 폭탄 | 느린 광역·예측 투척 | 궤적·착탄 예고 | 뭉친 골렘/슬라임에 최고 효율 |
| 드래곤 파이어 | 채널링 원뿔 지속 피해 | 마나·채널 중 이동 저하 | 전방 통로 봉쇄 |
| 메테오 | 지연 고위력 지역 공격 | 1초 위험/착탄 표식 | 거점 주변 대규모 구출 |
| 파이어볼 | 저비용 범용 스킬 | 마나 부족 | 다른 스킬 재사용 중 연결기 |

모든 적 공격은 위험도에 따라 500~1,000ms의 시각·음향 예고를 가진다. 즉사, 화면 밖 무예고 공격, 색 하나만으로 구별하는 공격은 금지한다.

## 7. 웨이브와 조우 문법

현재 적은 slime/golem/bat/dragon이고, 수량·HP·spawn gap이 선형 증가하며 도로 한 방향에서 접근한다. 목표 조우 문법은 다음 조건을 만족해야 한다.

- 스폰 방향 3개 이상: 큰길, 골목, 옥상/공중
- 비처치 목표 2개 이상: 시민 호송, 거점 수리/소화
- elite modifier 2개 이상: 보호막, 분열. 단 색만 바꾸지 않고 실루엣과 행동도 바꾼다
- 보스는 2단계 이상, 공격 패턴 3개 이상, 단계 전환 1초 이상의 명확한 신호
- 같은 웨이브 seed는 적 구성·드롭·목표를 재현한다

웨이브 1~2는 학습, 3~4는 도구 조합, 5는 첫 보스, 6~8은 복합 방향, 9는 자원 압박, 10은 두 번째 보스와 도시 방어 결산으로 설계한다.

## 8. 진행·보상

계정과 서버 없이 한 세션 안에서만 의미 있는 선택을 만든다. 영구 저장은 설정과 최고점수만 허용한다.

- 웨이브 2/4/6/8 종료 후 3개 강화 중 1개 선택
- 강화는 피해량 숫자만 올리지 않고 도구의 역할을 확장한다: 검 반사, 총 관통, 폭탄 점착, 메테오 수리 효과 등
- 스터드는 즉시 자원이고 강화 통화와 혼동하지 않는다
- 보상 풀 소진 때문에 드롭이 조용히 사라지면 경제 규칙 위반이다. 오래된 드롭 재활용 또는 명시적 상한 정책이 필요하다

## 9. 콘텐츠 목표표

| 콘텐츠 | 현재 | 품질 마일스톤 목표 |
| --- | ---: | ---: |
| 플레이 구역 | 직선 거리 1 | 상호 연결 구역 3 |
| 랜드마크 | 경찰서·크레인·헬기 | 기능성 랜드마크 5 |
| 일반 적 | 3 | 역할이 다른 6 |
| 보스 | 1 모델, 웨이브 5/10 | 2보스 또는 1보스 2변형 |
| 무기/스킬 | 3/3 | 3/3 유지, 강화 분기 추가 |
| 방어 목표 | 0 | 2 |
| 도시 생활 이벤트 | 장식 애니메이션 | 반복되지 않는 6 |

수량은 품질을 대체하지 않는다. 새 콘텐츠는 실루엣, 역할, 오디오, 성능, 출처 게이트를 모두 통과해야 표에 포함한다.

## 10. 승패·피드백·플레이테스트

- 승리: 웨이브 10과 최종 방어 목표 완료
- 패배: 플레이어 하트 또는 도시 무결도 0
- 결과 화면: 도달 웨이브, 점수, 처치, 시민 구조, 도시 무결도, 가장 큰 피해 원인을 보여준다
- 자동 분석/추적은 하지 않는다. 보호자가 보는 로컬 관찰표로 첫 행동 시간, 웨이브 1 완료, 도구 사용 다양성, 실패 원인을 기록한다
- 최소 10명 첫 사용자 테스트와 deterministic seed 20개를 거쳐야 밸런스 완료로 판정한다

## 11. 설계 완료 정의

P0 방어 규칙, 첫 60초 튜토리얼, 설정/접근성, 3방향 조우가 코드와 테스트에 존재하고, QA 문서의 하드웨어·아동안전·자산·배포 게이트가 모두 PASS일 때만 “고품질 브릭 시티 게임” 마일스톤을 완료한다.
