## 1. 감사 질문

1. 고품질의 정의가 계량 가능하고 현재 구현과 구분되는가?
2. 작업자가 다음 기능을 어디에 어떻게 만들지 규칙이 있는가?
3. 무료 외부 자산을 합법·재현 가능하게 반입하고 검증하는가?
4. 느리거나 깨진 버전이 main에서 자동 배포되는 것을 막는가?
5. 아동·접근성·브랜드·개인정보 위험을 제품 규칙으로 막는가?

보완 전 답은 대부분 아니었다. README와 44줄 작업 규칙은 기능 목록과 구현 습관만 설명했고, GDD/architecture/art/audio/asset ledger/quality gate/release runbook이 없었다.

## 3. Error급 발견

### E1. 설계와 완료 정의 부재

고품질 목표, session, defense 규칙, difficulty, content matrix, art/audio, 접근성, 하드웨어, release gate가 없었다. 결과는 “잘 만든 한 장면 prototype”이지 반복 생산 가능한 제품 체계가 아니었다.

조치: 7개 규격 문서와 본 감사/실행계획 작성, README·AGENTS·CLAUDE 연결. 상태: 통제 PASS, 콘텐츠 목표는 미완.

### E2. 공개 브랜드/URL 위험

서비스명·H1·repo/Pages 주소가 특정 완구 상표를 전면 사용했고 비공식 고지가 없었다. 공식 Fair Play는 비공식 사이트의 상표를 인터넷 주소에 넣지 말고, 서술적 사용 시 비후원·비승인 고지를 요구한다. 고지만으로 잘못된 사용이 치유되지는 않는다.

조치: 공개 제품명·canonical·shortcut·repo/Pages를 `브릭 시티`/`brick-city-defense`로 독립화하고 고지 추가. 공식 logo/리핑/세트 asset 차단. 상태: 기술 조치 후에도 상업화 전 법무 검토 필요.

### E3. 품질을 검사하지 않는 자동 배포

FPS 4도 green이고 Pages는 smoke 없이 배포됐다. 재현 가능한 package manifest/lock도 없었다.

조치: package lock, static gate, 실제 render pass cap 650/125k, 저장 차단/오디오 cap smoke, CI quality→deploy 의존, Action SHA pin, postdeploy build SHA. 상태: 코드 반영, CI 실행 증거 확인 필요.

### E4. 외부 자산 provenance 부재

icon도 prompt/model/date/hash 기록이 없고 external asset policy/manifest/NOTICE가 없었다. “무료”를 repo 재배포 가능으로 오해할 위험이 컸다.

조치: current asset manifest/SHA/NOTICE/icon provenance, allow/deny, 11단계 조달 gate, 후보별 공식 URL. 상태: 현재 자산 coverage PASS, 실제 외부 asset은 아직 0개.

### E5. 제품 약속과 실제 규칙 불일치

“시민·도시를 지킨다”고 설명하지만 적은 플레이어만 추적하고 시민은 도망만 간다. 시민 피해, 도시 HP, 구조, 거점, 방어 실패가 없다.

조치: GDD의 Defense Objective를 P0 blocker로 명시. 상태: FAIL/미구현. 구현 전 high-quality 판정 금지.

### E6. 작업 규칙 위반을 규칙이 잡지 못함

game.js가 보상·전투·이동·시민·수집까지 소유했고, COLORS only 규칙과 달리 직접 색상 93개였다.

조치: extract-first 구조와 line/color ratchet. 상태: PARTIAL. 증가 차단은 구현, 기존 부채 제거는 미완.
